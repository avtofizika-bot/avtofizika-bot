# AvtoFizika Bot — back-end сервер

Один сервер, который хранит системный промпт бота и отвечает на сообщения
клиентов из Telegram и с сайта, используя Anthropic API (Claude).

## Структура проекта

```
avtofizika-bot/
├── server.js          # вся логика сервера
├── systemPrompt.md     # системный промпт бота (база знаний, тон, правила)
├── package.json
├── .env.example        # шаблон переменных окружения
└── README.md
```

Чтобы изменить, что бот знает и как отвечает — редактируйте **только**
`systemPrompt.md`. Код в `server.js` трогать не нужно.

## Шаг 1. Установка

Понадобится Node.js версии 18 или новее (проверить: `node -v`).

```bash
cd avtofizika-bot
npm install
```

## Шаг 2. Настройка переменных окружения

```bash
cp .env.example .env
```

Откройте `.env` и заполните:

- `ANTHROPIC_API_KEY` — ключ API, получить на https://console.anthropic.com (раздел API Keys). Обязательно.
- `TELEGRAM_BOT_TOKEN` — токен бота, получить у **@BotFather** в Telegram (команда `/newbot`). Нужен только для Telegram-канала.

## Шаг 3. Запуск локально (для теста)

```bash
npm start
```

Сервер поднимется на `http://localhost:3000`. Проверить, что жив:
откройте `http://localhost:3000` в браузере — должна появиться надпись
"AvtoFizika bot server is running."

Локально Telegram не сможет достучаться до вашего компьютера напрямую —
для реального теста нужно задеплоить сервер (шаг 4) либо временно
пробросить локальный порт наружу через ngrok.

## Шаг 4. Деплой на бесплатный хостинг

Проще всего — **Render.com** или **Railway.app** (оба имеют бесплатный тариф,
достаточный для старта):

1. Зарегистрируйтесь, подключите GitHub-репозиторий с этим кодом (или загрузите файлы напрямую).
2. Создайте новый **Web Service**.
3. Build command: `npm install`
4. Start command: `npm start`
5. В настройках сервиса добавьте те же переменные окружения, что и в `.env` (ANTHROPIC_API_KEY, TELEGRAM_BOT_TOKEN).
6. После деплоя вы получите публичный URL вида `https://avtofizika-bot.onrender.com`.

## Шаг 5. Подключение Telegram

После деплоя пропишите Telegram, куда слать сообщения (webhook), один раз выполнив в браузере или через curl:

```
https://api.telegram.org/bot<ВАШ_ТОКЕН>/setWebhook?url=https://ваш-домен/webhook/telegram
```

Замените `<ВАШ_ТОКЕН>` на токен бота, а `https://ваш-домен` — на адрес,
который вы получили от Render/Railway. После этого все сообщения, которые
пользователи пишут боту в Telegram, будут приходить на ваш сервер
и обрабатываться Claude.

Проверить, что webhook установлен:

```
https://api.telegram.org/bot<ВАШ_ТОКЕН>/getWebhookInfo
```

## Шаг 6. Подключение чата на сайте

Виджет чата на сайте должен отправлять POST-запрос на:

```
POST https://ваш-домен/api/chat
Content-Type: application/json

{
  "userId": "уникальный-id-посетителя-сайта",
  "message": "текст сообщения от клиента"
}
```

Ответ:

```json
{ "reply": "текст ответа от бота" }
```

`userId` нужен, чтобы бот помнил историю переписки с конкретным
посетителем (можно использовать id сессии браузера/cookie). Если у вас
уже есть готовый чат-виджет (Tidio, Crisp и т.п.), нужно узнать у него,
поддерживает ли он "custom API endpoint" — тогда просто указываете туда
этот адрес. Если виджета ещё нет — можно заказать у разработчика простую
форму чата на сайте, которая будет стучаться в этот же `/api/chat`.

## Шаг 7. Instagram Direct (когда будете готовы)

В `server.js` есть закомментированная заготовка для Instagram —
раскомментируйте блок `webhook/instagram`, когда получите доступ
к Meta Business API (Instagram-аккаунт должен быть business-типа
и привязан к Facebook-странице). Понадобится:

- `INSTAGRAM_VERIFY_TOKEN` — придумываете сами
- `INSTAGRAM_PAGE_ACCESS_TOKEN` — выдаётся в Meta for Developers

Это самый долгий этап согласования (может занять от нескольких дней
из-за проверки Meta), поэтому имеет смысл запускать сайт и Telegram
раньше, а Instagram — параллельно, отдельным треком.

## Важно перед реальным запуском

- Прогоните 15–20 типичных вопросов клиентов (цена, гарантия, сроки,
  "фара запотевает", "разбилось стекло" и т.д.) и убедитесь, что бот
  не выдумывает цифры и корректно передаёт сложные случаи на менеджера.
- История диалогов сейчас хранится в оперативной памяти сервера
  (`Map` в `server.js`) — при перезапуске сервера она обнуляется.
  Для продакшена, если важно не терять контекст между перезапусками,
  стоит заменить на Redis или базу данных — можно сделать отдельным
  шагом, когда бот заработает и покажет себя на практике.
